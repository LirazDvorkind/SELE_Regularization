# Ground-truth SELE test set

18 ground-truth SELE profiles for scoring reconstruction methods, replacing the single
profile the project used before. Generated by `src/test_set/build_test_set.py` — re-run it
with `python -m src.test_set.build_test_set` after changing anything here.

## Contents

| Group | Count | Swept parameter | Source |
|-------|-------|-----------------|--------|
| `srv_*` | 6 | Surface recombination velocity, 1e3 … 1e7 cm/s | `Tamir_paper_SELE_figs/SELE_w_PR_vs_SRV.fig` |
| `tau_*` | 11 | SRH lifetime, 0.1 … 60 ns | `Tamir_paper_SELE_figs/SELE_W_2.FIG` |
| `paper_gt` | 1 | — (reference) | `Data/SELE_ground_truth.csv`, carried over unchanged |

`index.csv` lists every curve with its parameter value, summary statistics (surface value,
peak value, peak depth), and the paths to its depth, SELE, and G files — relative to `Data/`,
so a curve can point at a profile that already lives elsewhere instead of duplicating it.
That is how `paper_gt` reuses `SELE_ground_truth.csv`/`z_mesh.csv` rather than adding a
second 100k-point copy. Read the index by column name, not position.

## Layout

Every curve — including `paper_gt` — carries a G on each of two meshes, because they answer
different questions.

| File | Mesh | What it is |
|------|------|-----------|
| `curves/<id>/z_cm.csv`, `sele.csv` | the curve's own, from the source figure | the profile at the resolution it was simulated on |
| `curves/<id>/G.csv`, `ele.csv` | ″ | its own operator and the honest measurement |
| `curves/<id>/sele_500.csv`, `ele_500.csv` | linear solver mesh | the same profile as a reconstruction will see it |
| `solver_mesh/z_500.csv`, `G_500.csv` | linear solver mesh | shared operator — see below |

**Native-mesh G is per curve**, since the mesh is — but it is not always stored. G is a pure
function of the optical constants and the mesh, both of which are already in the repo, so
`paper_gt`'s 28×100000 operator (70 MB as text, 22 MB packed) is left out and rebuilt on
demand in ~0.5 s instead.

Each curve *declares* which applies, rather than leaving it to be inferred from a missing
file: `TestCurve.G_storage` is a `GStorage` of `FILE` or `COMPUTED`, and `index.csv` carries
it in a `G_storage` column. `load_native_G` dispatches on that value and raises on anything
it does not recognise; either path returns a bit-identical matrix.

**Solver-mesh G is shared.** On a fixed mesh it depends only on the optics, so it is
identical for every curve and stored once instead of eighteen times. `500` is the score
model's `target_length` and the mesh spans `W` from the score-grad config; both live in
`build_test_set.py`, which also emits any further resolutions added to
`_SOLVER_MESH_RESOLUTIONS`.

`paper_gt` is the only curve without `z_cm.csv`/`sele.csv` — it reaches the canonical profile
through the index instead.

## Units and conventions

The figures plot depth in µm and SELE in **percent**; both are converted on extraction, so
everything stored here is in the project's convention: depth in **cm**, SELE as a
**fraction**. The resulting range (7.6e-6 … 8.8e-3) sits inside the score model's trained
normalization range, so no rescaling is applied or needed.

## How the ELE is produced

Each profile keeps the non-uniform depth mesh of its source figure (0.005 … 350 µm), which
is unrelated to the solver mesh. The photogeneration matrix is therefore rebuilt **per
curve** on that curve's own mesh, and the measurement follows as `eta = G @ S`. Every
(SELE, ELE) pair is thus exactly self-consistent, on both meshes.

Because SELE is sampled *at* depths while G is defined *per element*, mesh edges are placed
midway between consecutive samples (`edges_from_samples`), pinning the front edge to the
surface.

### Optical constants

G is built from the paper's own ellipsometry constants via `src/optical_constants.py`, which
reads `Tamir_paper_SELE_figs/Optical constants GaAs.fig` (bit-identical to `MATLAB SELE
Simulation/optical_constnats_w_wo_Drude.mat`). That module is the project's single source of
optics, so **the test set and the solver share one forward model**: `solver_mesh/G_500.csv` is
bit-identical to what `calc_mesh_and_G` builds. An earlier `Data/k.csv` held a single
extinction spectrum that differed from these by up to ~7% and could not express the
free-carrier split at all; it has been deleted.

The paper carries two absorption coefficients (main text §2.2, SI §S2). `alpha`, from the
model *with* the Drude oscillator, sets how fast the beam is attenuated. `alpha_b`, with the
Drude term removed, sets how many of those absorption events free a carrier — free-carrier
absorption is intra-band and generates nothing. Generation therefore carries the prefactor
`alpha_b / alpha`, as in SI eq. S4.1; over 400–670 nm it runs 0.976–0.998.

Reflectance does not enter: `phi_abs = phi_0 * A` normalizes it out of eq. 4, and since
`exp(-alpha * 350 um)` underflows to zero across the whole measurement band there is no
back-surface or multi-pass contribution to recover.

### Cross-check

The recomputed `paper_gt` ELE tracks the historical MATLAB-exported `Data/ELE_sim.csv` at a
median ratio of 0.96 (0.83–1.02 across the band). The offset is expected and traceable:
`ELE_sim.csv` predates this procedure, having been produced from the old `k.csv` with no
`alpha_b/alpha` factor. Before those two changes the same comparison gave 0.99, which is what
validates the mesh and units handling. The solver now uses these same optics, so it and the
measurement it is fitting no longer disagree.

## Consuming the set

Use `src/test_set/loader.py`:

```python
from src.test_set.loader import (
    load_test_set, load_native_G, load_on_solver_mesh, resample_to_mesh)

for curve in load_test_set():                    # native mesh: z_cm, sele, ele
    G = load_native_G(curve.curve_id)            # its own operator: curve.ele == G @ curve.sele
    solver = load_on_solver_mesh(curve.curve_id) # G, sele, ele on the 500-point mesh
    S_gt = resample_to_mesh(curve, z_edges)      # any other mesh; by depth, never by index
```

`load_test_set` deliberately leaves G out — carrying `paper_gt`'s 28×100000 operator on
every load is not worth it — so fetch it per curve with `load_native_G`, which reads or
rebuilds it as appropriate.

Resample by depth, not by index — these meshes span 350 µm while the solver mesh spans
`W` (~30 µm), so index-based resampling would compress the profile onto the wrong depths.

Two caveats when scoring reconstructions on the solver mesh:

- **Which ELE is the observation.** `ele_500.csv` is consistent with `G_500.csv` by
  construction, which makes residuals interpretable but is an inverse crime. `ele.csv` is
  the harder, more honest target: it was generated on the native mesh and sits ~2% away
  (up to 10%, and 41% at the shortest wavelength for `paper_gt`), a bias no solver can fit
  away.
- **The surface value is not representable.** The first element centre of the 500-point mesh
  is at 0.03 µm, deeper than the figures' 0.005 µm surface sample, so `sele_500[0]` is an
  interpolated value rather than SELE(z=0). Truncation at 30 µm, by contrast, is free: it
  changes the ELE by exactly zero.

`python -m src.test_set.plot_test_set` renders an overview of both sweeps for eyeballing.
